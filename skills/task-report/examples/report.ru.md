# Notes — замер «до»: скорость списка заметок на iPhone

Сколько стоят сценарии списка заметок в приложении до оптимизации, где уходит время и что с этим делать. Читать тому, кто берёт шаги `03`–`12` под-эпика `58/2` («производительность списка»), и тому, кто сверяет вердикт «после» с числами «до».

Все числа сняты на iPhone 15, сборка Debug, в состоянии `Nominal` (телефон не греется), если рядом не сказано иное. Release не мерили.

## 1. Вывод

1. **Медленно всё, что целиком меняет модель списка или трогает каждую строку списка заметок.** Форма настроек папки закрывается за 118 / 483 / 1312 мс при пороге 100 мс (на 300 / 2400 / 9000 заметках). Один тик плотности на 9000 заметках — около 3,4 с главного потока.
2. **Время сидит в раскладке списка заметок, а не в фиксации слоёв Core Animation.** При «Save» почти вся раскладка — вызов UIKit, который пишет в лог предупреждение о высотах строк. При прокрутке на каждое событие обходятся все строки списка, хотя на экране их около дюжины.
3. **Вторая статья расхода — проход сниппетов:** синхронная отрисовка превью строк с форматированным текстом. Это 45–70 % занятого главного потока при нажатии клавиши в поиске.
4. **Что делать.** Список заметок: шаги `05` (плотность, прокрутка) и `05a` («Save», Undo, Redo). Проход сниппетов: шаги `09` и `10`. Открытие приложения на 9000 заметках: шаг `07`.
5. **Что не даст выигрыша.** Шаг `03` («одна транзакция Core Animation»): на пути приложения фиксация и так одна.
6. **Предел связей с тегом 9000 не поднимается.** Пересчёт связей с тегом при перетаскивании уже выходит за 8,0 мс.
7. **Рамки чисел.** Debug, один телефон. Прокрутка и щипок сняты по одной записи на размер.

## 4. Почему медленно

### 4.1. «Save» и Undo: раскладка списка и лишний лог высот строк

1. Касание «Save» запускает на главном потоке проход сниппетов, затем `noteList.setModel`.
2. `noteList.setModel` перекладывает список заметок. Раскладка стоит 38 / 196 / 688 мс.
3. Почти всё это время (31 / 174 / 612 мс) — вызов `_NSLogv` внутри UIKit: функция пишет предупреждение о недопустимых высотах строк.
4. Запись настроек папки на диск (94 / 466 / 1418 мс) идёт вне главного потока и интервал не удлиняет.

Доля вне прохода сниппетов — 64 / 289 / 961 мс. Она сама больше порога на 2400 и 9000 заметках: это даёт шаг `05a`. Undo смены сортировки идёт тем же путём.

Текст предупреждения UIKit не прочитан: у приложения в записи нет консоли. Первое действие шага `05a` — прочитать его из лога Debug-сборки.

### 4.2. Прокрутка: обход всех строк на каждое событие

Каждое событие прокрутки обходит **каждую строку списка**: строк столько же, сколько заметок, и все живы всегда. Цена события растёт с библиотекой, хотя на экране видно около дюжины строк. На `updateRelativeDate` уходит 44 / 73 / 79 % занятого главного потока.

Решение: вход для шага `05` — обходить видимые строки вместо всех. Окно видимых строк прохода сниппетов (шаг `10`) прокрутку не лечит: до прохода сниппетов она не доходит.

### 4.3. Плотность: тик не укладывается в кадр

Тик не укладывается в кадр ни на одном размере, даже без миниатюр. Цена на заметку растёт с размером: 116 → 163 → 376 мкс. Гипотеза Research «раскладка линейна по числу заметок» не подтвердилась; причину разбирает шаг `05` первым делом.

### 4.4. Предел связей с тегом 9000

Модельный кадр перетаскивания на тег, связанный со всеми 9000 заметками, выше 8,0 мс в обоих замерах (раздел 5). Решение не меняется: предел не поднимается ([Decisions.md](Decisions.md), строка 181).

### 4.5. Поиск и открытие приложения

Оба сценария упираются в проход сниппетов: построение превью с подсветкой и их раскладку. Сам поиск (28–92 мс) идёт вне главного потока. Шаг `03` здесь выигрыша не даёт: фиксаций Core Animation в интервале нет. Открытие приложения превышает порог только на «Архиве» после запуска, на 120–231 мс.

## 7. Как воспроизвести и где сырые данные

**Библиотеки.** Ставятся из меню разработчика («Пресеты библиотек»); подробно — [Testing.md](Testing.md) §9. После сценария, который меняет библиотеку, библиотеку удаляют и ставят заново.

**Тесты (нижняя граница).** Классы плана `NoteListPerformance`; команды — [Testing.md](Testing.md) §8. Сверяется строка `Executed N tests`, а не баннер.

**Профили.** Запись шаблоном Animation Hitches:

```bash
xcrun xctrace record --template 'Animation Hitches' --instrument os_signpost --instrument 'Thermal State' \
  --device <UDID> --time-limit 60s --no-prompt --output <файл>.trace --launch -- com.example.notes
```

**Где трассы.** `PerfTraces/58-2-02/` в рабочей копии `notes-perf`, вне git: 54 файла `.trace`, около 22 ГБ. Имя трассы начинается с размера: `p-` (300), `d-` (2400), `a-` (9000). Рядом с трассой лежит `<имя>.json` с разбором.

**Правило термосостояния.** Число, снятое не при `Nominal`, в таблицу не идёт: прогон повторяют после остывания.
